## Deviations from deploy prompt v2
- Route binding: `custom_domain: true` was specified in deploy prompt's Step 2 wrangler.jsonc template but rejected by Cloudflare API ("Wildcard operators (*) are not allowed in Custom Domains"). Resolved by switching to `zone_name: "astrant.io"` — semantically equivalent for routing; wildcard DNS already provisioned via the dashboard handles the per-subdomain certs.
- Verification host: deploy prompt assumed `pharos-customer-mcp.pharos-dev.workers.dev` for internal API calls, but the workers.dev preview URL is not enabled for this Worker (custom routes only). Used `api.mcp.astrant.io` instead (matches `*.mcp.astrant.io/*` route; the slug-match regex in index.ts allows any subdomain to hit `/api/internal/*` since the internal-router runs before the slug check).
- Initial provision test had wrong config schema (`customer_name`/`industry`/`target_keywords` instead of `brand_name`/`description`/`capabilities`/`pricing`/`case_studies`/`contact_tools`). Caught immediately when well-known returned `undefined` placeholders; re-provisioned (operation=updated_renewal) with correct schema. No locked-content drift.
