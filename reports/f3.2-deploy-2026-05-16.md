### V-B observation (locked)

**Dodo does NOT fire any webhook on `cancel_at_next_billing_date` toggles** (verified via 60+ seconds of tail observation after successful cancel API call). The `subscription.cancelled` event only fires at the actual period_end date when the subscription transitions for real. Same likely true for reactivate (Dodo dashboard reflected the change but no webhook arrived). Tail confirmed zero `POST /api/dodo-webhook` events during the test window.

**Implication**: the `subscription.reactivated` branch added to dodo-webhook in this slice may never fire in practice. The V-B pivot path for `subscription.updated` likely also unnecessary. Both remain harmless if they don't fire.

**Real implication**: D1 row stays `status='active'` between cancel-click and period_end (the webhook never lands to flip it to cancelled). The D13 client-side flip is session-only. Customer who refreshes /account after canceling sees "Active — renews..." + Cancel button again, looking like the cancel didn't take effect. **Real UX gap for production.** F3.2.1 followup: add `cancel_pending_at INTEGER` column to subscriptions; set in our cancel handler on success; D7 render-state checks it alongside D1.status. ~10 lines + 1-statement migration.
