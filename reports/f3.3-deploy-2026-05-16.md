## Memory candidates queued (post-ship)

1. **Trace from canonical source, not derived rendering**: when a rendering layer reformats content (PDF text extraction silently converts em-dash → `--`, drops italic markers, flattens pipe-table cells), regex authoring against the rendered output silently fails when the source content lacks the rendered artifact. Always V-read the source generator (e.g., `digest-template.ts`), not the post-render artifact (e.g., PDF samples). Adjacent class to "external-API V-read at SPEC v1" memory.

2. **Gmail blocks `data:` URI images in email body**: hosted URLs required for inline images. CID-attached images via Resend's attachment.content_id field also typically gated behind Gmail's "Display images below" prompt. Pattern: when delivering brand imagery in email, host the asset on a public CDN (here: marketing-site `/brand/`) rather than inlining as data URI.

3. **WinAnsi (CP1252) coverage is broader than I assumed**: bullet (•), em-dash (—), en-dash (–), smart quotes (" " ' '), ellipsis (…), multiply (×) all map natively. Only characters genuinely outside CP1252 need substitution for pdf-lib StandardFonts: ≥ ≤ → ← (and others outside the 8-bit subset). Overly-defensive substitution loses typography fidelity needlessly.

4. **Sharp chroma-key + trim recipe for non-alpha PNGs**: when source PNG is 3-channel (no alpha) with content-on-bg structure, generate transparent variant via:
   ```js
   .ensureAlpha().raw().toBuffer({resolveWithObject:true}).then(({data,info}) => {
     for (let i = 0; i < data.length; i += 4) {
       const lum = Math.round((data[i] + data[i+1] + data[i+2]) / 3);
       data[i+3] = 255 - lum;  // alpha = inverse luminance
       data[i] = 0; data[i+1] = 0; data[i+2] = 0;  // force RGB to black (or target color)
     }
     return sharp(data, {raw: {width, height, channels: 4}})
       .trim({threshold: 5})  // drop transparent edges
       .resize(W, H, {fit: 'contain', background: {alpha: 0}})
       .png().toFile(out);
   });
   ```
   Useful pattern for marketing-site light-variant assets that lack alpha. The trim step is critical for visual alignment — without it, the rendered image has invisible padding that shifts the visible content rightward of its bounding box.
